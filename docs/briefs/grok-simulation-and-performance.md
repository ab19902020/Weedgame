# Brief for Grok · Simulation depth, performance and test infrastructure

You own **how the world behaves and how fast it runs**: traffic, pedestrians, police, buses, signals, audio, performance and the test harness. Another agent (Astra 6.2) owns geodata, tile geometry, materials and landmarks at the same time. Keep to your files (listed below) so the two branches merge cleanly.

## Start here

1. Repo `ab19902020/Weedgame`, branch `ccr-0546346a-2h4fov` at commit `9ac9064` or later. Create your own branch `grok/sim-perf` from it.
2. Read: `CLAUDE-PROMPT.md` (the brief), `README.md` (build, run, layout), `docs/COVERAGE.md` (especially "Acceptance run" and "Still to do") and `docs/captures/acceptance.json`. That log shows exactly what each acceptance step did.
3. Set up:
   ```bash
   npm install && npm run build && npm run serve      # http://localhost:8080 (world data is already committed)
   xvfb-run -a node tools/test/acceptance.js /tmp/acc  # full touch-driven run, ~90 min at ~1 fps software GL
   ONLY="cross at,police" xvfb-run -a node tools/test/acceptance.js /tmp/acc   # subset by step-name keywords
   ```
   You don't need the OSM pipeline unless you consume new data fields (see the contract below).

## Ground rules (non-negotiable)

- **Sandbox only.** No missions, objectives, calls, deliveries or sales. Police encounters must come out of the simulation, stay proportionate and fictional, show no injury detail, and always end cleanly with control returned to the player.
- **Cal and Leon are the only playable characters.** Everyone else is an NPC.
- **No fabricated numbers.** Performance figures must name the hardware and backend they came from. Figures from the container's software renderer say nothing about phones; label them as such.
- **Audio licences.** Recorded sounds only if CC0 or similar, each logged in `docs/SOURCES.md`. Synthesis is fine.
- **Don't commit APKs.** The signing key is gone; the user rebuilds after merging.

## Tasks, in priority order

1. **Performance budget for the Honor Magic 6 Pro (30 fps target).** Nobody has run the game on a phone yet.
   - Cut draw calls. Each LOD0 tile has about 8 meshes. Merge per-tile ground, markings and struct where materials allow, batch LOD1 buildings, and cull whole tile groups by distance and frustum.
   - Cap shadow distance and resolution per quality preset.
   - Write explicit `low` / `medium` / `high` budgets: tiles, draw calls, triangles, people, vehicles, cloud steps, pixel ratio. The existing dynamic resolution holds about 30 fps by adjusting the pixel ratio.
   - Add a scripted **perf flythrough**: a dev-panel button drives a fixed route (Woodley precinct → A3290 → Reading town centre) and saves `perf-*.json` through `GCNative.savePerf` on Android. Users will run it on the phone.
   - Write `docs/PERF-CHECKLIST.md` so the user can collect real device numbers: backend shown, fps, p95 frame time, stalls, heap.
2. **Persistent traffic state.** Only player-touched and owned vehicles are saved today. Save the simulated fleet near both brothers (ids, routes, edge and position) so swapping or relaunching restores the same cars. Keep the save under 1 MB.
3. **Traffic behaviour.**
   - Lane choice for turns: use `turnLanes` if present, otherwise UK rules (right turn → offside lane).
   - Right turns give way to oncoming traffic.
   - Roundabout lane discipline.
   - Buses use bus lanes when the `psv` flag is present.
   - Signals become demand-actuated: approach detectors extend greens and skip empty stages.
   - Keep blocked-lane recovery and the junction-box rule.
4. **Pedestrians.**
   - Walk on mapped footways and sidewalks where they exist; build a walk graph that joins footways to road pavements.
   - Route to building doors (`doors` from Astra, if present; otherwise the frontage edge midpoint) and enter or leave buildings out of view.
   - Round corners at junction mouths instead of cutting across.
   - Tune density by district and time, for example a Saturday afternoon on Broad Street versus a Woodley close at dawn.
5. **Police.**
   - Make dispatch reliable on long routes.
   - Add a second incident type that fits the sandbox, such as a broken-down car blocking a lane (recovery truck plus patrol), or a noise complaint at a pub at night. Keep it fictional and non-graphic.
   - Add a foot chase on foot offences.
   - Let pursuits continue when the player leaves the road graph.
   - Each must resolve cleanly.
6. **Trains (stretch).** Run trains on the Reading–Waterloo line (Earley, Winnersh, Wokingham, Bracknell) and the Great Western main line at Reading, with station stops and timetable-free headways. Use `manifest.stations` from Astra if present.
7. **Test infrastructure.**
   - Give `walkTo` real pathfinding on the walk graph; today it walks straight lines.
   - Make the acceptance run resilient to dev-panel layout changes by tapping buttons by id or data attribute.
   - Add `node --test` unit tests for pure logic: `network.route`, signal stage cycling, the weather timeline and wet/dry integration, save round-trip and legacy migration.
   - Add `npm run test` and `npm run acceptance:quick`.

## Data contract with Astra (world data)

Feature-detect, never require:

- `net.turnLanes`: per half-edge index into `net.names`, or −1.
- `net.psv`: per-edge bus-lane flag.
- `tile.data.doors`: `[x, z, buildingIndex, isShop]`.
- `manifest.stations`: `[name, x, z, platformEdgeIndices]`.

Until these exist, use the fallbacks described above.

## Gotchas already found

- The camera auto-follow on foot only re-centres while the stick is pushed forward. Re-centring on sideways input causes a spin loop.
- "Get in" prefers the active brother's own car. Cars occupied by the other brother can't be entered.
- Buses whose OSM route leaves the map continue as normal traffic (`notInService`).
- Responding police stop about 10 m short of the scene and re-route if they overshoot.
- Teleports snap to the nearest road and stand you on its pavement. After a teleport, wait for `!GC._needGround` before sending camera drags, or the drags pile up.
- CDP touch: every `Input.dispatchTouchEvent` must list *all* active touches. Sending a single-finger event ends any other held finger.
- `?sim=N` runs N simulation substeps per rendered frame. `?fixedres=1` disables dynamic resolution for captures.
- Never rebuild `www/` while a browser test is running.
